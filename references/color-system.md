# 配色选择、颜色角色与状态

## 选择依据

先看品牌约定、任务密度、内容类型和使用环境，再选择中性色与强调色。下表是自配候选及审美建议，具体色值见 [基础配色数据](../assets/color-palettes.json)。这些方案不是官方品牌配色，也不保证某种颜色会产生特定心理或业务效果。

| 方案 | 可考虑的场景 | 使用要点 |
| --- | --- | --- |
| 冰白 · 钴蓝 | 后台、数据工具、效率产品 | 冷白与浅灰承载内容，蓝色集中用于操作与选中。 |
| 雾白 · 深青 | AI 助手、知识库、管理工具 | 轻微绿灰背景搭配深青操作；成功状态配合明确文案和图标。 |
| 浅灰 · 森林绿 | 阅读、生活服务、长期记录 | 近中性底色为主，绿色局部强调，避免所有模块染绿。 |
| 冷灰 · 鸢尾紫 | 创作、笔记、学习与设计工具 | 收敛的紫色实色与清楚的文字层级搭配，是否使用渐变由内容需要决定。 |
| 珍珠灰 · 海军蓝 | 专业服务、企业门户、品牌页面 | 海军蓝承担操作；可选金色只作少量装饰，不能直接配白色小字。 |
| 淡灰粉 · 桑葚紫 | 文化内容、作品集、生活方式品牌 | 背景轻微带色，操作使用较深主色；错误提示保持独立语义。 |
| 午夜蓝 · 冰青 | 开发工具、监控、技术产品 | 深色区域分层，亮青按钮配深字；调色画布另设中性背景。 |
| 石墨灰 · 青柠 | 媒体工具、编辑器、专业工作台 | 深灰承担主体，青柠只用于关键操作与少量标记；专门调色区使用更中性的灰。 |

本用户希望少用“杏色＋红色＋黑色”的成套默认搭配。把这一偏好用于方案排序；已有明确品牌时结合品牌处理。红色仍可表达适当的危险或错误语义，深色文字也仍可保证阅读。

## 先分角色，再取色值

| 角色 | 用途与检查 |
| --- | --- |
| `background`、`surface` | 页面和内容表面。用适当明暗差表达区域；需要清晰边界时补充边界线。 |
| `text`、`muted` | 正文与辅助文字。辅助层级仍需清楚，不能借极浅文字隐藏必要信息。 |
| `primary`、`onPrimary` | 主操作实色与其上的文字。前景和背景成对定义。 |
| `primaryHover`、`primaryPressed` | 悬停与按下。检查文字对比和边界；按下不表示操作完成。 |
| `selection` | 持续选中底色。搭配勾选、边条、标签或语义属性，和瞬间按下区分。 |
| `borderSubtle`、`borderControl` | 装饰分隔与需要辨识的控件边界分别管理；浅分隔色不能直接承担所有输入框的必要边界。 |
| `focusRing` | 键盘焦点。外环与控件保留合适间隙，检查实际相邻背景；不以仅悬停样式替代。 |
| `disabledBackground`、`disabledText` | 真正不可用的状态。说明必要原因，避免与只读混淆；不可挪作正常辅助文字。 |
| `semantic` | 成功、信息、警告、危险提示各有背景和文字组合；独立于品牌色管理。 |

数据中的调色板包含以上基础角色；语义色按明暗模式分组。阴影、遮罩、次级按钮或特定业务状态可按项目补充，不把基础数据描述成完整组件库。

中性灰可以偏蓝、绿、紫或保持纯灰，与强调色协调。Radix 对中性色配对及不同色阶用途提供了参考：[配色组合](https://www.radix-ui.com/colors/docs/palette-composition/composing-a-palette)、[色阶用途](https://www.radix-ui.com/colors/docs/palette-composition/understanding-the-scale)。

按角色管理颜色、让主题替换角色的值而保留意义，参考 [Carbon 颜色体系](https://www.carbondesignsystem.com/building-blocks/foundations/color/overview) 与 [Atlassian 颜色角色](https://atlassian.design/foundations/color)。

## 和状态一起设计

- 主按钮默认、悬停、按下和处理中保持同一角色；进行中通过文案、忙碌指示和可用性变化反馈，通常不需要变成绿色。
- 成功、失败和警告需要清楚的文字或图标；品牌恰好为绿色或红色时，更应区分操作与结果语义。
- 处理结束后更新实际内容和可操作项。颜色变化、提示消失、进度条满格都不能单独作为成功依据。
- 明暗主题单独配置表面层次、文字、边界、焦点与状态色。内容图片、视频和第三方标志不随主题被整体反色。

## 对比检查

普通文字一般采用至少 4.5:1，大号文字在符合定义时可采用 3:1；需要通过颜色辨识的必要控件或图形边界，要按实际相邻颜色检查适用的非文本对比要求。装饰分隔线不等于必要控件边界，禁用状态的例外不能用于正常内容。

文字阈值、非文本条件和额外状态线索分别参考 [WCAG 文字对比](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[非文本对比](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)、[颜色的使用](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html)。

可在技能目录运行：

```text
node scripts/check-palette-contrast.cjs
```

脚本用 sRGB 相对亮度计算数据内明确的文字、按钮、选中、边界、焦点与语义色对；使用未四舍五入的比值判断。它不检查真实页面、混合透明背景、字号、焦点几何或色觉区分，不能代表整个产品已通过可用性或 WCAG 验证。修改颜色后重新检查相关色对，并在实际界面查看。
