# 字体选择、中英搭配与排版层级

## 选型与角色

先确定中文、拉丁字符、数字与代码各由什么字体显示，再定义标题、正文、控件和辅助文字的样式。下表按场景提供候选，不把某一字体固定为所有产品的默认。

| 方向 | 字体候选 | 采用与边界 |
| --- | --- | --- |
| 通用工具 | 思源黑体 SC 或 Noto Sans SC＋Inter | 关注中文小字、中英混排与数字。思源与 Noto 的具体文件、名称和地区版本要按下载资源确认，无需同时加载两套用途重复的中文字体。 |
| 技术工作台 | IBM Plex Sans SC＋IBM Plex Sans；代码按需用 Plex Mono | 同家族协调中英文，日志与代码局部使用等宽字体。 |
| 几何感品牌页面 | 思源黑体 SC＋Manrope | 英文标题与中文搭配时检查视觉粗细和大小；不能只换英文便宣称中文整体风格改变。 |
| 文化与编辑内容 | 思源宋体标题＋思源黑体正文与控件 | 宋黑对照形成层次。长文是否使用宋体正文按设备与阅读任务试排，密集控件单独检查。 |
| 亲切、手写感 | 霞鹜文楷短标题或引语＋黑体功能区 | 局部建立内容气质；不要直接假定适合所有小字、数字与高密度操作。 |
| 平台原生 | 平台系统字体与明确的中文后备 | 减少额外加载，接受不同系统字形差异；跨平台品牌一致性有要求时再选自托管字体。 |

字体官方资料：[思源黑体](https://github.com/adobe-fonts/source-han-sans)、[思源宋体](https://github.com/adobe-fonts/source-han-serif)、[Inter](https://rsms.me/inter/)、[IBM Plex](https://www.ibm.com/design/language/typography/typeface/)、[Manrope 项目](https://github.com/davelab6/manrope)、[霞鹜文楷](https://github.com/lxgw/LxgwWenKai)。风格和场景匹配属于设计建议。

## 排版起点

下列数值是试排起点。结合设备、屏幕缩放、文字长度和实际字形调整；不要把它们当成通用标准或自动验收阈值。

| 角色 | 字号起点 | 字重起点 | 行高起点 |
| --- | --- | --- | --- |
| 工具界面正文 | 14–16px | 400 | 1.5–1.7 |
| 长文正文 | 16–18px | 400 | 1.7–1.9 |
| 按钮、导航与输入 | 14–16px | 400–500 | 1.3–1.5，并保证控件高度 |
| 辅助说明 | 12–13px | 400 | 1.4–1.7；必要信息不能因层级变得难读 |
| 分区标题 | 20–28px | 500–600 | 1.3–1.5 |
| 页面标题 | 28–40px | 500–600 | 1.2–1.4 |
| 品牌展示标题 | 按内容与设备从 32–64px 试排 | 按字体选择 | 检查中文上下沿、换行和窄屏效果 |

使用字体实际提供的字重。不同家族相同的数值不保证视觉等粗，缺失字重还可能被合成。装饰字体、文楷等字体按其实际资源选型，不强求 500 或 600。

优先用字号、字重、行距与留白形成层次，增加家族应有明确作用。中文不直接套用英文标题的极紧字距；字形密度、标点与换行需要单独检查。

## 中英文、数字与回退

字体选择会按字形回退。中文界面应查看开发工具显示的实际渲染字体，而不只检查 CSS 中写了哪个名字。[MDN 字体匹配与回退](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/font-family)

跨平台自托管字体可采用类似的家族顺序，实际名称按加载资源调整：

```css
/* 前两项需要实际加载；后续为后备。 */
font-family: "Inter", "Noto Sans SC", "PingFang SC", "Microsoft YaHei", sans-serif;
```

平台原生方案优先使用系统 UI 家族，不要求下载或再分发系统字体。缺少字体时保留可读的通用后备，测试中英混排、标点、括号、货币符号、0/O、1/l/I 和常见生僻字。

表格数值、金额、时长和计时器按需使用 `font-variant-numeric: tabular-nums`，并确认当前字体支持。它让数字宽度稳定，不等于需要整段等宽字体；[Inter 官方特性](https://rsms.me/inter/) 列出了等宽数字等功能。

## 和组件状态、布局一起验证

- 用真实长度的默认、处理中、成功与失败文案试排，如“保存”“正在保存…”“重试保存”。按钮预留足够空间，避免状态变化挤动相邻控件；窄屏允许合理换行。
- 字体加载或字重变化后检查标题折行、表格对齐、输入高度、提示位置与焦点环，防止文字被固定高度裁切。
- 重要错误说明与恢复操作保留足够字号和对比。不能因其处在辅助区域而缩小到难以阅读。
- 读取中、空结果与任务完成后的文案应保持同一套字体角色，不依靠突然加粗所有文字表达状态。

## 加载与资源

只加载需要的家族与字重；中文字体考虑 WOFF2、合理分片或按需子集。动态内容和用户输入需要足够字形覆盖，静态标题子集不能直接替代完整正文资源。字体加载失败后页面仍应可操作，并检查回退时的布局变化。

上线或交付资源时确认所用字体版本的许可和必要附带文件，区别系统使用、网页嵌入与打包分发。字体推荐不等于自动获得任意再分发权限。
