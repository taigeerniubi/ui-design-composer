# 模式库与适用边界

按当前问题查阅：阅读与视觉动线、页面骨架、信息与交互、辅助规律。表中的建议用于选择方案，不构成固定模板。

## 阅读与视觉动线

下面五种行为见于 NN/g 的眼动研究，实际出现方式受任务、内容、排版和阅读方向影响。

| 模式 | 行为与适用情境 | 设计用途与边界 |
| --- | --- | --- |
| F 型扫描 / F-pattern | 在部分文字密集内容中，先横扫上方，再短距离横扫，随后偏向内容左侧向下扫。 | 识别正文右侧、下方被忽略的风险；重要信息前置，用有意义的标题和分组帮助定位。它描述内容阅读，不等于顶部导航加左侧栏。 |
| 层状蛋糕 / Layer-cake | 主要扫描标题与小标题，找到相关部分后阅读其正文。 | 设置页、帮助文档和功能说明可通过清晰的标题层级支持这种行为。标题要概括内容，留白要使归属明确；无需给每个短句加标题。 |
| 斑点式 / Spotted | 在分散的关键词、数字、链接或视觉突出内容之间跳读。 | 查找价格、日期、参数和状态时，让相关字段容易识别。过度加粗、变色会削弱区分。 |
| 割草机式 / Lawn-mower | 在表格等内容单元中，逐行左右往返扫描。 | 支持横向比较，保持行列对齐、单位一致、标签清晰。内容展开后若破坏对应关系，会增加比较成本。 |
| 专注阅读 / Commitment | 用户有强动机，阅读全部或大部分内容词。 | 支持阅读说明和学习材料，保持文字易读、逻辑连贯；用户愿意细读时，分组和明确的小标题仍有帮助。 |

来源：[文本扫描模式](https://www.nngroup.com/articles/text-scanning-patterns-eyetracking/)、[F 型的误解与边界](https://www.nngroup.com/articles/f-shaped-pattern-reading-web-content/)、[层状蛋糕](https://www.nngroup.com/articles/layer-cake-pattern-scanning/)、[割草机式扫描](https://www.nngroup.com/articles/lawn-mower-pattern/)。

下面两种主要作为布局启发，避免承诺用户必然沿指定路线阅读。

| 方法 | 如何理解 | 使用边界 |
| --- | --- | --- |
| Z 型 / Z-pattern | 按左上、右上、左下、右下组织构图。 | 可以尝试用于信息较少的首屏，安排入口、核心内容和下一步。真实注意力仍受图片、对比、内容与任务影响。 |
| 古腾堡图式 / Gutenberg diagram | 用四个象限及左上至右下的阅读倾向讨论构图。 | 更适合作为信息较均匀时的参考；不能据此断言某个角落总最重要，或按钮放右下就一定有效。 |

参考：[IxDF 视觉层级](https://ixdf.org/literature/topics/visual-hierarchy)、[视觉层级与广告设计研究](https://www.theartsjournal.org/index.php/site/article/download/78/77/153)。阅读方向不同的语言需要重新判断，不能照搬左上起点。

## 页面骨架

| 布局 | 适合什么任务 | 采用时检查什么 |
| --- | --- | --- |
| 便当盒 / Bento grid | 用大小不同的矩形模块展示异质内容，如产品功能与概览。 | 模块大小是否体现真实优先级；阅读顺序是否清楚。不要为凑格子拆散连续任务。 |
| 瀑布流 / Masonry | 浏览高度不同的图片与作品，重视视觉发现。 | 加载是否引发跳动、键盘顺序是否清楚。需要逐项参数比较时，规则网格或表格通常更便于对齐。 |
| 分屏 / Split screen | 两个互补区域，如说明与表单、预览与设置。 | 两侧是否都必要，比例是否符合任务，窄屏如何排序。无需强求五五分。 |
| 主从 / Master–detail | 从列表选择对象并查看、处理详情，如邮件、文件与记录。 | 选中状态、返回列表的位置、未保存修改，以及窄屏切换时的上下文。 |
| 多栏工作台 | 编辑器、设计工具等需同时访问对象、画布、属性与时间轴的任务。 | 主工作区是否足够，面板是否能按需收起，当前对象是否明确。窄屏可转为任务面板切换。 |

## 信息组织与交互

| 方法 | 采用条件与做法 | 常见失效方式 |
| --- | --- | --- |
| 信息层级 / Visual hierarchy | 通过字号、对比、位置和留白表达重要程度，让主任务与辅助信息容易区分。 | 多个同等醒目的按钮或大标题争夺注意；用太浅的文字表达次要层级，影响可读性。 |
| 分组与分块 / Grouping、Chunking | 根据用户理解的关系组织标签、字段和操作，用接近、间距与必要的边界表达归属。 | 按技术模块分组；相关控件被拆散；每个字段都套卡片。 |
| 渐进式披露 / Progressive disclosure | 常用与必需内容先展示，低频进阶内容通过明确入口展开。 | 高频功能藏得深；已生效的重要设置没有摘要；必填错误藏在折叠组里。 |
| 情境化操作 / Contextual actions | 在选中对象、编辑位置或相关状态附近展示适用操作。 | 无选中时毫无线索；功能只在悬停时出现；切换对象后仍显示旧对象的参数。 |
| 识别优于回忆 / Recognition over recall | 用预览、最近使用、可辨识标签和历史记录减轻记忆负担。 | 只留难懂的图标；要求用户记住上一步数据或精确文件名。 |
| 可供性与操作线索 / Affordance、Signifiers | 区分对象实际能做什么，以及外观如何提示该操作；为点击、输入、拖动提供可理解的线索。 | 把纯装饰画得像按钮；拖动无入口、无替代操作；交互元素看不出可操作性。 |
| 系统状态可见 / Visibility of system status | 为保存、上传、生成和提交显示可理解的当前状态与结果。 | 点击后无响应；假进度；错误只出现在短暂提示中且无法恢复。 |
| 直接操控 / Direct manipulation | 操作目标可见且反馈及时，例如拖动对象、调整边缘、直接编辑文字。 | 手柄太小；预览与结果脱节；精确操作没有数值输入或键盘替代。 |
| 合理默认值 / Sensible defaults | 用符合常见任务的初始值减少重复选择，必要时记住适当范围内的偏好。 | 默认值掩盖重要后果；跨项目记忆造成误用；恢复默认不清楚。 |
| 错误预防 / Error prevention | 用约束、即时校验、输入格式和后果提示减少可预见错误。 | 禁用按钮不解释原因；校验过早打断输入；每个低风险操作都要求确认。 |
| 撤销与恢复 / Undo、Recovery | 对可逆修改提供撤销、历史或可恢复删除；失败后保留输入并提供下一步。 | 宣称可以撤销但无法恢复；删除即时生效且没有恢复；重试清空已填内容。 |
| 一致性 / Consistency | 相同含义使用一致的命名、位置与交互，复用产品和平台的已有约定。 | 相同按钮结果不同；为视觉统一把不同任务强行做成同一流程。 |
| 分步完成 / Wizard | 有实际依赖顺序、阶段产出或明显认知负担的流程，可逐步推进。 | 把很短的表单拆成多页；后退丢失输入；无法查看和修改前面的决定。 |

使用上表时，可结合 [NN/g 可用性启发式](https://www.nngroup.com/articles/ten-usability-heuristics/) 检查系统状态、用户控制、一致性、错误预防与恢复。这些是设计判断的参考，具体方案仍需结合任务验证。

## 辅助规律

- **希克定律 / Hick’s Law**：在其适用的选择任务中，更多或更复杂的选项会增加决策时间。用分类、清晰命名和合理默认值降低选择负担；不因此机械删除有用选项。
- **菲茨定律 / Fitts’s Law**：指向目标的距离和尺寸影响操作时间。让高频目标容易触达、点击区域充足；同时考虑误触、遮挡与不同输入设备。
- **格式塔原则 / Gestalt principles**：接近、相似、连续与共同区域等线索影响人如何感知分组。用它们表达真实关系，避免视觉分组与业务含义冲突。

这些规律辅助解释设计取舍，不直接给出通用的按钮数量、字号、卡片尺寸或面板比例。
